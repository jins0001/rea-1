# Q3. 엑셀 같은 프로그램을 만들려고 할 때, REA로 엑셀을 리버싱할 수 있나요?

**짧은 답: 기술적으로 "들여다보기"는 조금 되지만, 엑셀을 따라 만들 목적이라면 하면 안 되고, 해도 거의 소용없습니다.**
대신 **훨씬 쉽고 합법적인 길**이 있습니다.

---

## 1. 기술적으로는? → "일부만, 아주 어렵게"

| 확인할 것 | 결과 |
| --- | --- |
| 엑셀 종류 | Windows용 네이티브 프로그램 (`EXCEL.EXE`, C++로 만든 것) |
| REA의 Windows 지원 | **실험 단계**. Ghidra(무료) + Java(JDK 21 이상)를 직접 깔아야 함. **읽기 전용** 분석만 가능 |
| 엑셀 크기 | 프로그램 파일만 수백 MB, 코드는 수천만 줄로 알려져 있음 |
| 유튜브 실험 | 작은 앱 하나를 23분 동안 다시 만들었고, 결과물은 **949줄, 74점** |

> **비유:** 유튜브 실험이 "레고 자동차 하나 보고 따라 만들기"였다면,
> 엑셀은 "**비행기 공장 전체**를 밖에서 보고 따라 짓기"입니다.
> 돋보기(REA)로 나사 몇 개는 볼 수 있어도, 공장 전체를 따라 짓는 건 불가능에 가깝습니다.

## 2. 법적으로는? → "하면 안 됩니다" ❌

1. **마이크로소프트 사용 약관**: 법이 특별히 허락하는 경우를 빼고 **리버스 엔지니어링·디컴파일을 금지**합니다.
2. **한국 저작권법 제101조의4 (프로그램코드역분석)**: 다른 프로그램과 **호환(서로 연결)** 시키는 데 꼭 필요한 정보를 얻을 때만 좁게 허용합니다.
   그렇게 얻은 정보로 **비슷한 프로그램을 만드는 데 쓰는 것은 금지**입니다.
3. **REA 자체 규칙(DISCLAIMER.md)**: "남의 프로그램 코드를 그대로 베끼는 것"은 돕지 않는다고 적혀 있습니다.

→ "엑셀을 만들려고 엑셀을 리버싱"하는 건 **딱 금지된 경우**에 해당합니다.

> 유튜브 실험이 괜찮았던 이유: 유튜버가 **자기가 가진, 공개(MIT) 라이선스 앱**으로 했기 때문입니다.

## 3. 그럼 엑셀 같은 걸 만들려면? → 리버싱이 필요 없습니다 ✅

엑셀 같은 프로그램은 이미 **설계도가 공개된 것**이 많습니다.

| 방법 | 설명 |
| --- | --- |
| **엑셀 파일 형식(.xlsx) 공부** | `.xlsx`는 **국제 표준(ECMA-376 / Office Open XML)** 이라 규칙이 공개 문서로 나와 있습니다. 리버싱 없이 읽기/쓰기 가능 |
| **오픈소스 스프레드시트 참고** | LibreOffice Calc 같은 **소스 코드가 공개된** 프로그램은 코드를 그냥 읽으면 됩니다 (라이선스 규칙은 지켜야 함) |
| **기존 라이브러리 사용** | 웹: SheetJS, Handsontable / Python: openpyxl, pandas 등 이미 만들어진 부품을 가져다 씀 |
| **엑셀 공식 설명서** | 함수(SUM, VLOOKUP 등)가 어떻게 계산되는지 마이크로소프트가 공개해 둠 |
| **AI에게 직접 부탁** | "셀, 수식, 저장 기능이 있는 간단한 스프레드시트를 웹으로 만들어 줘" → 바로 만들 수 있음 |

## 4. REA를 꼭 써 보고 싶다면? (합법적인 연습)

- **내가 만든 프로그램**을 REA로 분석해 보기
- **오픈소스 프로그램**(MIT 등 허용 라이선스)으로 연습하기 — 유튜브 실험처럼
- **CTF(해킹 대회) 연습 문제**처럼 분석하라고 만든 파일 사용하기

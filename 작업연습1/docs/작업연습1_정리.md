## 2. 설명 — 왜 이게 되는가

### 2-1. exe 안에 남는 것

컴파일은 "사람 말 → 컴퓨터 말" 번역입니다. 번역해도 **내용(규칙)은 남습니다.**

| 원본 소스에 쓴 것 | C# exe 안에 남은 모습 | Go exe 안에 남은 모습 |
| --- | --- | --- |
| `if (s < 40) return "F";` | 숫자 `40`, 글자 `"F"`, 함수 이름 `Grade` | `< 0x28` (16진수 40), 주소 `&DAT_1400b2cc8` |
| `Average(scores)` | 함수 이름 `Average` + 부르는 관계 | 이름 사라짐, `grade` 안에 합쳐짐 |
| `"average={0:F1}"` | 글자 그대로 | 글자 그대로 (주소로 연결) |

> **비유:** C#은 "요약 노트", Go·C는 "구워진 케이크". 노트는 읽으면 되지만, 케이크는 맛보고 재료를 추측해야 합니다.

### 2-2. 겉으로는 모르는 규칙

| 입력 | 출력 | 겉으로 본 의문 | 분석으로 찾은 답 |
| --- | --- | --- | --- |
| 99 98 97 | `A+` | "+"는 왜? | 숫자 **95**, 글자 **"+"** → 전부 95↑이면 "+" |
| 100 100 30 | `F` | 평균 76.7인데 왜 F? | 숫자 **40**, 바로 **"F"** → 40 미만 과목 있으면 과락 |

### 2-3. 분석만으로는 부족한 것

1차 시험에서 315개 중 **12개 불일치**:

```text
입력 80 81 81 95  (평균 84.25)
  원본        : 84.3   ← .NET은 5에서 올림
  다시 만든 것 : 84.2   ← Python 기본은 짝수 쪽으로
```

이 차이는 분석 보고서 어디에도 안 나옵니다. **시험해야만** 찾을 수 있습니다. → 고친 뒤 315/315.

## 4. 질문과 답

### Q1. REA 자료(도구)가 없으면 힘든가요?

**아니요, 다른 도구로도 할 수 있습니다. 다만 REA가 있으면 편하고, AI에게 맡기기 좋습니다.**

| 하고 싶은 일 | REA 없이 쓸 수 있는 도구 | REA를 쓰면 |
| --- | --- | --- |
| C# exe 분석 | ILSpy, dnSpy (오히려 C# 코드를 바로 보여 줌) | 숫자·글자·호출 관계를 **JSON으로** 정리해 줌 |
| 기계어 exe 분석 | Ghidra를 직접 화면에서 조작 | 명령 한 줄로 Ghidra를 **화면 없이** 실행 |
| 안드로이드 앱 | JADX GUI | 같은 방식의 명령 + JSON |
| AI에게 맡기기 | 도구마다 따로 연결해야 함 | **MCP 하나로** Claude Code가 전부 사용 |

> 이 연습에서도 exe 속 글자(#US 구역)는 REA가 번호표만 줘서, **Python으로 직접 읽어** 연결했습니다(`summarize.py`의 `user_strings`). 이렇게 일부는 손으로도 할 수 있습니다.

**REA의 진짜 장점**

1. **한 가지 사용법**: exe, apk, 웹사이트… 대상이 달라도 명령 모양과 결과 형식(JSON)이 같음
2. **근거(Evidence)**: 결과마다 파일 지문(SHA-256), 사용 도구 버전, 한계가 같이 기록됨 → 보고서 신뢰도 ↑
3. **AI 연결**: Claude Code가 직접 분석 → 다시 만들기 → 시험까지 할 수 있음

### Q2. REA 코드는 어떻게 활용했나요?

**REA 소스 코드를 고치지 않고, "완성된 REA 프로그램"을 명령어로 불러서 썼습니다.**

```text
jins0001/rea (소스, TypeScript 35만 줄)
      │  같은 코드가 빌드되어 npm에 올라감
      ▼
npm install -g rea-agents@6.4.0   ← 노트북에 설치한 것
      │
      ▼
우리 스크립트(.ps1) ──"rea inspect-managed-members ..."──▶ REA ──▶ JSON 결과
                                                                  │
우리 Python(summarize.py) ◀─────────── JSON 읽기 ─────────────────┘
      │
      ▼
분석결과.md (사람이 읽는 보고서)
```

| 사용한 REA 명령 | 어디서 | 결과에서 꺼내 쓴 칸 |
| --- | --- | --- |
| `inspect-managed-artifact` | 2_분석하기 | 파일 종류, 지문 |
| `inspect-managed-members` | 2_분석하기 | `methods[].signature`(입출력), `body.anchors`(숫자·글자 번호), `call_edges`(호출 관계) |
| `inspect-artifact` | 4_도전 | 파일 신분증 |
| `decompile --provider ghidra` | 4_도전 | `normalized_result`(의사 코드) |

> **비유:** REA 소스 코드는 "자동차 설계도", 설치한 REA는 "완성된 자동차". 우리는 설계도를 고친 게 아니라 **차를 운전**했습니다.
> 저장소 소스는 "어떤 명령이 있는지", "결과 JSON이 어떤 모양인지" 확인할 때 **설명서처럼** 읽었습니다 (예: `docs/managed-code-analysis.md`).

## 2. REA는 무엇을 하는 도구인가요?

REA는 **Reverse Engineer Anything(무엇이든 거꾸로 분석하기)** 의 줄임말입니다.

### 리버스 엔지니어링이 뭐예요?

- 보통 프로그램은 **설계도(소스 코드) → 완성품(프로그램)** 순서로 만듭니다.
- 리버스 엔지니어링은 반대로 **완성품을 보고 → 어떻게 만들었는지 추측**하는 것입니다.

> **비유:** 맛있는 과자를 먹고 "이건 밀가루, 설탕, 버터가 이 정도 들어갔겠다"라고 성분을 알아내는 것과 비슷합니다. 레시피(소스 코드)는 없지만, 과자(프로그램)를 꼼꼼히 살펴서 알아내는 거죠.

### REA의 특별한 점: AI 비서와 연결된다

REA는 **AI 에이전트(Claude Code, Cursor, Codex 같은 AI 코딩 도우미)** 가 분석 도구를 쓸 수 있게 이어 주는 **"연결 다리"** 역할을 합니다. 이 연결 방식을 **MCP**라고 부릅니다.

```
나 ──질문──▶ AI 에이전트 ──MCP──▶ REA ──▶ 분석 도구(Ghidra, Hopper 등)
                                             │
나 ◀──설명/코드── AI 에이전트 ◀──근거와 결과──┘
```

예를 들어 이렇게 AI에게 부탁할 수 있습니다.

> "메모 앱의 검색 기능이 어떻게 작동하는지 조사하고, 근거를 보여 준 다음, 내 프로젝트에 비슷한 기능을 만들어 줘."

그러면 AI가 REA를 이용해 앱을 살펴보고, **무엇을 알아냈는지 + 그 근거 + 아직 모르는 것**을 정리해 줍니다.

## 5. 프로젝트 속은 어떻게 생겼나요?

### 규모

| 항목 | 숫자 |
| --- | --- |
| 전체 파일 | 약 3,200개 |
| 주요 언어 | TypeScript (JavaScript에 "자료형 검사"를 더한 언어) |
| TypeScript 파일 | 약 2,400개 |
| 코드 줄 수(src 폴더) | 약 35만 줄 |
| 테스트 파일 | 약 890개 |
| 버전 | 6.4.0 |

> 35만 줄이면 A4 용지로 약 7천 장! 한 사람이 아니라 많은 사람이 함께 만든 **대형 프로젝트**입니다.

### 주요 폴더

| 폴더 | 하는 일 (비유) |
| --- | --- |
| `src/` | 본체 코드 — **자동차의 엔진** |
| `src/cli/` | 터미널에서 명령어로 쓰는 부분 — **운전대** |
| `src/server/` | AI와 대화하는 MCP 서버 — **무전기** |
| `src/ghidra/`, `src/hopper/`, `src/ida/` | 유명 분석 도구와 연결 — **공구함 연결 부품** |
| `bridge/` | 분석 도구 안에서 돌아가는 작은 프로그램(Python, Java, Swift) — **통역사** |
| `tests/` | 잘 작동하는지 검사하는 코드 — **품질 검사원** |
| `docs/` | 사용 설명서 — **설명서** |
| `website/` | 홈페이지(rea.tools) — **가게 간판** |
| `third_party/` | 다른 사람이 만든 도구들 — **빌려온 공구** |

### 사용된 언어

- **TypeScript** — 대부분의 코드
- **Python** — Hopper, pwntools 연결
- **Java** — Ghidra 연결
- **Swift** — macOS 기능
- **C** — 테스트용 예제 프로그램

## 6. 어떻게 써 보나요?

컴퓨터에 **Node.js**(22.19 이상)가 깔려 있으면 됩니다.

```bash
# AI 에이전트에 REA 연결하기
npx rea-agents setup

# 터미널에서 직접 JavaScript 앱 분석하기
npx -y rea-agents@latest analyze-javascript-application "D:/apps/example" --json
```

깊은 분석(.exe 같은 프로그램)을 하려면 **Ghidra**(무료), **Hopper**, **IDA** 중 하나가 따로 필요합니다.

## 8. 질문: "이거 프로그램 개발하는 건가요?"

**답: 반은 맞고 반은 다릅니다.**

| 관점 | 설명 |
| --- | --- |
| **REA 자체** | ✅ 프로그램 개발 맞음. TypeScript로 35만 줄을 짠 **소프트웨어 프로젝트**입니다. |
| **REA로 하는 일** | 🔍 새 프로그램을 만드는 게 아니라, **이미 있는 프로그램을 분석하는 도구**입니다. |
| **jins0001/rea** | 📋 원본을 **복사만 해 둔 상태**라서, 아직 직접 개발한 부분은 없습니다. |

정리하면:

- **REA를 "사용"하는 것** = 분석 작업 (돋보기로 들여다보기)
- **REA를 "고치거나 기능 추가"하는 것** = 프로그램 개발 (돋보기 자체를 개선하기)
- **REA로 알아낸 걸 내 앱에 넣는 것** = 내 프로그램 개발에 활용

> **비유:** REA는 "현미경"입니다. 현미경을 **만드는 회사**는 개발을 하고, 현미경을 **쓰는 과학자**는 관찰(분석)을 합니다. 지금 저장소는 현미경 설계도를 복사해 온 상태예요.
